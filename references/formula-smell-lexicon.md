# 財務モデルにおける「AI臭・素人臭」アンチパターン辞典（Formula Smell Lexicon）

本ドキュメントは、LLMや初学者がExcel財務モデルを作成した際に高確率で発生する「素人臭」「AI臭」「バグ温床」となるモデリング悪癖・アンチパターンの辞典である。
モデル納品前、またはエージェントによるコード生成・数式編集時に必ずチェックし、該当する箇所を排除すること。

---

## 1. 数式構造のアンチパターン（Formula Architecture Smells）

| アンチパターン | 具体例 | なぜ悪手か（理由） | 正しい書き方（ベストプラクティス） |
| :--- | :--- | :--- | :--- |
| **式内定数ハードコード<br>（Magic Number in Formula）** | `=E12*1.05`<br>`=E20*0.30` | 後から前提変更（成長率が5%→3%等）があった際に修正漏れが発生する。監査者が前提条件を一覧できない。 | 必ず前提条件セル（例: `C5`）に成長率を置き、`=E12*(1+$C$5)` と参照する。 |
| **SUM関数内の個別定数加算** | `=SUM(D10:D14)+500` | 最悪のバグ温床。SUMの中身だけ見て合計されていると錯覚し、外出しの定数が見落とされる。 | 定数は別行の勘定科目（例:「その他調整額」）として行を起こし、SUMの範囲内に含める。 |
| **IFERROR によるエラーの隠蔽** | `=IFERROR(D15/D16, 0)` | 深刻な参照切れ（`#REF!`）やゼロ除算（`#DIV/0!`）を握りつぶし、異常な数値を正常値として流してしまう。 | 原則として使わない。分母が0になり得る場合のみ `=IF(D16=0, 0, D15/D16)` と明示的にガードする。 |
| **複雑怪奇なネストIF** | `=IF(A1=1, B1, IF(A1=2, C1, IF(A1=3, D1, E1)))` | 可読性が最悪で、モデル引継ぎ時や監査時にロジック追跡が不可能になる。 | `CHOOSE` 関数または `XLOOKUP` / `INDEX-MATCH` を用い、シナリオ選択テーブルを組む。 |
| **Excel循環参照の有効化頼み** | 「反復計算を有効にする」にチェックを入れないと計算できない金利計算 | ファイルを開く環境によって計算が発散・クラッシュする。投資銀行・ファンドでは提出即刻リジェクト。 | **期首残高ベース金利（Beg Debt × Rate）** を採用し、循環参照を構造的にゼロにする。 |
| **逆引き参照（将来セルへの参照）** | 過去列（D列）が将来列（E列）のセルを参照している | 時間軸の因果律が破壊され、監査者が時系列を追えなくなる。 | 数式は常に「左から右（過去から将来）」「上から下（前提から帰結）」の一方向に流す。 |

## 2. 貸借・現預金のアンチパターン（Balance Sheet & Cash Smells）

| アンチパターン | 具体例 | なぜ悪手か（理由） | 正しい書き方（ベストプラクティス） |
| :--- | :--- | :--- | :--- |
| **BS現金を直接ハードコード** | 将来の現預金セルに勝手な予測値を直打ち | キャッシュフロー計算書（CF）との連動が破綻し、現金の裏付けのない計画になる。 | 現預金は常に **「期首現預金 ＋ 当期CF増減」のプラグ計算** とする。 |
| **BS貸借差額の隠蔽プラグ** | 「その他資産」や「雑損失」に `資産合計 - 負債純資産` の差額を無理やり足す | 貸借が一致しているように見せかけた粉飾・モデル破綻の隠蔽。 | チェック行 `Check: 資産合計 - 負債純資産合計` を設け、差額が厳密に 0 になるよう各スケジュールを正しく組む。 |
| **マイナス現預金の放置** | 資金ショートしているのに現預金が `-5,000` のまま進行 | 企業として倒産・デフォルト状態であることを見落とす。 | リボルバー（当座貸越・短期借入）スケジュールを連動させ、現預金下限を下回った場合は自動借入を発生させる。 |
| **減価償却費のCapex無視** | 設備投資を行っているのに減価償却費を前年同額で据え置き | 固定資産台帳（PP&Eロールフォワード）が連動しておらず、非現実的な利益が出る。 | **PP&Eスケジュール（期首 ＋ 投資 － 償却 ＝ 期末）** を必ず独立して組む。 |

## 3. 表記・セマンティクス・色彩のアンチパターン（Formatting & Visual Smells）

| アンチパターン | 具体例 | なぜ悪手か（理由） | 正しい書き方（ベストプラクティス） |
| :--- | :--- | :--- | :--- |
| **入力値が黒字（または計算式が青字）** | 全ての文字が黒（#000000）のまま | どこが前提条件でどこが計算式か一目で判別できず、他人が前提を変更できない。 | **青字（#0000FF）＝手入力前提値、黒字（#000000）＝計算式、緑字（#008000）＝他シート参照** を100%徹底。 |
| **同一項目で正負の符号が混在** | 費用項目がある列では正の数（`500`）、別の列では負の数（`-500`） | SUM計算時に二重減算や意図せぬ加算バグが多発する。 | PL費用は正の数で統一し計算で引くか、全表で支出をマイナス表示にするか、モデル全体で厳格に統一する。 |
| **無意味な小数点以下の氾濫** | 売上高が `1,234.5678百万円` と表示 | 一桁台の端数に意味はなく、経営判断・プレゼンテーション資料として極めて見づらい。 | 百万円単位・千円単位なら整数表示（`#,##0`）、比率・倍率は小数第1位または第2位（`0.0%`、`0.0x`）に統一。 |
| **ド派手な原色グラデーション** | 蛍光イエロー、鮮やかな赤、紫の網掛け | 投資銀行・ファンド・経営会議の場にそぐわない安っぽい印象を与える。 | ヘッダーは濃紺（#1B365D）またはチャコールグレー（#333333）に白文字。塗りは抑制的に使う。 |
