# 財務モデリング設計規約（modeling-rules.md）

本規約は、投資銀行（IBD）・プライベート・エクイティ（PE）ファンド・戦略コンサルティングファームの実務水準に基づく、**財務モデリングExcel構築の絶対正典（SSOT）**である。
エージェントおよびモデラーは、財務モデルを設計・構築・修正する前に本規約を熟読し、すべてのルールを遵守しなければならない。
成果物のExcelファイルは、`scripts/check_model.py` による機械チェックで **FAIL 0** を達成することを納品要件とする。

## 1. 色彩・視覚設計規約（Color & Visual Coding）

財務モデリングにおいて、色の使い分けは「装飾」ではなく**「データの性質（出自と役割）を即座に判別するためのセマンティックコード」**である。

### 1-1. 文字色（Font Color）の厳格な4大原則
- **§1.1 青字（Blue / `#0000FF` または `#002060`）: ハードコード（直接入力・前提数値）**
  - 外部資料からの転記値（決算書実績値、売上高、原価、期末残高など）や、モデラーが任意に設定した前提数値（売上成長率 2.0%、目標原価率 35.0% など）は、**必ず青字**で表記する。
  - 数値が直接打ち込まれているセルが黒字であってはならない。
- **§1.2 黒字（Black / `#000000`）: 計算式（Formula）**
  - 四則演算（`+`, `-`, `*`, `/`）や集計関数（`SUM`, `AVERAGE` 等）など、同一シートまたはモデル内で算出されるセルは**必ず黒字**で表記する。
  - 実績列であっても、小計・合計（売上総利益、営業利益、資産合計等）は黒字の数式とする。
- **§1.3 緑字（Green / `#008000` または `#0070C0`）: 別シート・外部参照（Cross-Sheet Link）**
  - 多シートモデルにおいて、別シート（`inp` や `calc`、`debt`）から数値を参照しているセルは**緑字**とする。
  - 例: `IS` シートで `=calc!D15` や `=debt!D8` と参照する場合。
- **§1.4 赤字（Red / `#FF0000`）: 警告・エラー・チェック不一致**
  - バランスシートの貸借差額（差額 ≠ 0）や、キャッシュショート、負債限度額超過などのエラーフラグ・警告表示にのみ赤字を使用する。

### 1-2. 背景色（Fill Color）の運用
- **§1.5 入力可能セル（Input Cell）の着色**:
  - ユーザーやクライアントが数値を打ち替えて感応度を試す「前提パラメータ入力セル」には、**薄いオレンジ（`#FFF2CC` または `#FCE4D6`）**または**薄い黄色（`#FFFFCC`）**の背景色を施し、入力可能箇所を一目で判別できるようにする。
- **§1.6 見出し・ヘッダー行の着色**:
  - セクション見出しや年次ヘッダー（2023A, 2024E等）は、**ネイビー（`#1B365D`、白抜き文字）**または**濃いグレー（`#D9D9D9`、黒太字）**で統一する。原色や派手な配色は厳禁。
- **§1.7 網掛け（Stripe/Hatch）の禁止**:
  - 印刷時やPDF変換時に潰れる原因となるため、セルの網掛けパターンは使用しない。

## 2. シート・レイアウト・時間軸規約（Layout & Timeline）

モデルの構造は、誰が見ても直感的に計算の流れ（ストーリー）が追えるように物理配置しなければならない。

### 2-1. 時間軸の絶対ルール
- **§2.1 時間軸は常に「横方向（列方向）」**:
  - 過去の実績から将来の予測値へと、時間は必ず**左から右（列方向）**へ流れる（例: C列＝2022A実績、D列＝2023E、E列＝2024E…）。
  - 縦方向に年次を展開することは絶対に禁止する。
- **§2.2 実績（Actual）と予測（Estimate/Forecast）の明記**:
  - ヘッダー行には必ず `2022A`（Actual）や `2023E`（Estimate）、`2024F`（Forecast）を記載し、どの列からが予測値であるかを明確に区切る。
  - 実績列と予測列の間に細い区切り線を入れるか、ヘッダー色を微細に変えて境界を可視化する。

### 2-2. 列の役割分担（Standard Column Mapping）
単一シート・多シートを問わず、列の役割は左から右へ統一する：
- **§2.3 A列: エレベーターコラム（Section Jump Navigation）**:
  - A列には各セクションのタイトル（例: `（１）前提`、`（２）損益計算書`、`（７）貸借対照表`）のみを配置し、途中の行は空欄にする。
  - モデラーや経営陣が `Ctrl + ↓ / ↑` を押すことで、目的のセクションへ一瞬で上下ジャンプできるようにする。
- **§2.4 B列: 財務諸表・モデル項目名（Line Item Label）**:
  - 科目名、スケジュール項目名、単位（百万円等）を記載する。
  - 階層構造がある場合はインデント（全角スペース1個またはインデント設定）を使い、親子関係（売上高 → 製品売上、サービス売上）を視覚化する。
- **§2.5 C列: 基準年・直近実績値（Base Year / Historicals）**:
  - 予測のアンカーとなる直近期の実績数値を配置する。
- **§2.6 D列以降: 将来予測期間（Projection Period）**:
  - 通常は5年間（中期経営計画期間）、必要に応じて10年間の予測を展開する。

### 2-3. シートの並び順（Multi-Sheet Flow）
多シートモデルを組む場合、シートの並び順は「計算の依存関係」に忠実に左から右へ並べる：
1. `Cover`（表紙、前提サマリ、目次、更新履歴）
2. `inp`（共通前提、マクロ経済変数、過去財務データ実績）
3. `calc`（運転資本スケジュール、固定資産・減価償却スケジュール）
4. `debt`（借入金返済・新規借入スケジュール、支払利息計算）
5. `IS`（損益計算書 / Income Statement）
6. `BS`（貸借対照表 / Balance Sheet）
7. `CF`（キャッシュフロー計算書 / Cash Flow Statement）
8. `Valuation` / `DCF`（FCF計算、WACC、ターミナルバリュー、感応度分析）

## 3. 計算式・数式設計規約（Formula Engineering）

数式は、財務モデルのエンジンである。シンプルで、透明で、壊れにくい数式を設計する。

### 3-1. 符号規約（Sign Convention）
符号の扱いはモデル全体の成否を左右する。ネオビスタ財務規約では以下の**「自然加算原則」**を適用する：
- **§3.1 費用・流出は「マイナス値」で保持する原則**:
  - 売上原価、販管費、支払利息、設備投資（Capex）、配当金などの**キャッシュアウト・費用項目はマイナス数値（例: `-4,150`）として格納**する。
- **§3.2 合計は単純な `+` または `SUM` で集計する**:
  - 費用がマイナスで入っているため、売上総利益は `=売上 + 売上原価`（`=C16+C17`）、営業利益は `=売上総利益 + 販管費`（`=C18+C19`）と、すべて自然な足し算で集計される。
  - これにより、「ここで引くのか足すのか」の符号ミスを構造的に撲滅する。
- **§3.3 前提パラメータの符号**:
  - 前提シートで「売上原価率 35%」と入力された場合、PL側では `=-売上高 * 原価率`（`=-D16*D4`）としてマイナス値を生成する。

### 3-2. 数式の一貫性と右展開（Consistency & Drag-Right）
- **§3.4 1行1数式（Consistency across columns）**:
  - 予測期間（D列〜H列等）において、同一行の数式は**すべての列で同一の構造**でなければならない。
  - 「3年目だけ特別に手入力する」「5年目だけ数式を変える」ことは厳禁。例外が必要な場合は、フラグ行（Switch）を設けて数式内で吸収する。
- **§3.5 実績列（C列）の小計も数式にする**:
  - 実績データであっても、売上総利益、営業利益、税引前当期利益、資産合計などの集計項目はベタ打ちせず、必ず数式（`=SUM(...)` や `=C16+C17`）で組む。これにより、数式をそのまま右側の予測列へコピー展開できる。

### 3-3. 循環参照の完全防止（No Circular References）
- **§3.6 期首残高・期末残高基準の徹底**:
  - 支払利息や受取利息の計算において、当期末残高をそのまま利息計算に使うと「当期利益 → 内部留保 → 現金/借入 → 利息 → 当期利益」の循環参照が発生する。
  - 原則として、**利息計算は「期首残高ベース（Beginning Balance）」**または**返済前残高**で行い、循環参照を物理的に発生させない。
  - どうしても期中平均（Average Balance）を使う場合は、Excelの反復計算オプションに依存しない構造を作るか、サーキュラーブレーカースイッチ（ON/OFFセル）を設ける。

### 3-4. 複雑なネスト・ブラックボックスの禁止
- **§3.7 1セル内3階層以上のIFネスト禁止**:
  - `IF(IF(IF(...)))` のような複雑怪奇な数式は禁止。条件分岐が多い場合は、計算行を複数ステップ（フラグ行、上限判定行など）に分割する。
- **§3.8 数値のハードコード埋め込み禁止**:
  - 数式の中に直接数値を埋め込む（例: `=D16*1.05` や `=E22*0.3`）ことは絶対に禁止。
  - 必ず `1.05`（成長率）や `0.30`（税率）は前提セル（D3やD6）として切り出し、セル参照でリンクさせる。

## 4. 3表連動アーキテクチャ規約（3-Statement Integration）

財務モデルの核心は、損益計算書（PL）、貸借対照表（BS）、キャッシュフロー計算書（CF）の完全な調和と連動にある。

### 4-1. 3表連動のゴールデンルート（7ステップ）
モデルは必ず以下の順序で連動・完結させなければならない：
1. **PL作成**: 売上高から税引後当期純利益（Net Income）までを計算。
2. **有形固定資産スケジュール（PP&E Schedule）**:
   - `期末PP&E = 期首PP&E + 設備投資(Capex) - 減価償却費`
3. **利益剰余金スケジュール（Retained Earnings Schedule）**:
   - `期末利益剰余金 = 期首利益剰余金 + 当期純利益 - 配当支払`
4. **運転資本スケジュール（Working Capital Schedule）**:
   - 売掛金、棚卸資産、買掛金を回転日数または売上・原価比率で予測。
   - `Δ運転資本 = 前期運転資本 - 当期運転資本`（キャッシュフローへの影響額）を算出。
5. **借入金スケジュール（Debt Schedule）**:
   - `期末借入金 = 期首借入金 - 約定返済 + 新規借入`
   - 利息をPLの金融費用へフィードバック。
6. **キャッシュフロー計算書（CF）の導出**:
   - 営業CF ＝ 当期純利益 ＋ 減価償却費 ＋ Δ運転資本
   - 投資CF ＝ 設備投資（Capex）
   - 財務CF ＝ 借入増減 ＋ 配当支払
   - `期末現金残高 = 期首現金残高 + 営業CF + 投資CF + 財務CF`
7. **貸借対照表（BS）の完成とバランスチェック**:
   - 資産側の「現預金」に**CFの期末現金残高をダイレクトリンク**。
   - 資産合計と負債・純資産合計の差額を計算し、全年度で **差額 ＝ 0** であることを検証。

### 4-2. バランスチェック行（Balance Check Row）の義務化
- **§4.1 貸借差額チェック行の常設**:
  - BSの直下に必ず `バランスチェック（差額）` 行を設け、`=資産合計 - 負債純資産合計` を計算する。
  - 全ての予測年度において、差額が `0.00`（許容誤差 1円/1千円未満）であることを確認する。
- **§4.2 OK/ERROR フラグ**:
  - `=IF(ABS(差額)<0.01, "OK", "ERROR - CHECK BS")` のようなバリデーション判定を表示し、異常を一瞬で検知できるようにする。

## 5. DCF・バリュエーション規約（Valuation & Returns）

事業計画から企業価値（EV）および株式価値を算定する際の規約。

### 5-1. フリーキャッシュフロー（FCF）の定義
- **§5.1 アンレバードFCF（FCFF）の厳格な算式**:
  ```
  FCF = 営業利益(EBIT) * (1 - 実効税率) 
        + 減価償却費(D&A) 
        - 設備投資(Capex) 
        - 運転資本増加額(ΔWC)
  ```
  利息の支払いはWACC（割引率）側で考慮するため、FCFFの計算には支払利息を含めない（アンレバード）。

### 5-2. 割引計算と年央調整（Mid-Year Convention）
- **§5.2 年央調整の適用**:
  - キャッシュフローは年末に一括して発生するのではなく、期中に平均して発生するため、ディスカウントファクターは `(1 + WACC)^(t - 0.5)`（年央調整）を用いることを標準とする。

### 5-3. ターミナルバリュー（TV）と感応度分析
- **§5.3 永久成長率法（Gordon Growth）とマルチプル法の併記**:
  - 予測最終年度の翌期FCFに基づく永久成長率法（一般に0%〜1.5%程度）またはEBITDAマルチプル法を用いてTVを算出する。
- **§5.4 感応度マトリクス（Sensitivity Table）の常設**:
  - 割引率（WACC）× 永久成長率（PGR）、または WACC × Exitマルチプル の2軸で、株式価値または株価の感応度分析テーブル（Excelの `TABLE` 機能または配列計算）を必ず併設する。

## 6. 表記・単位・フォント規約（Typography & Units）

見た目のプロフェッショナリズムは、モデルの信頼性を担保する最後の砦である。

### 6-1. フォント指定
- **§6.1 英数字主体のモデル**: `Arial`, `Calibri`, または `Segoe UI`（9pt〜10pt）で統一。
- **§6.2 日本語混在モデル**: `Meiryo UI` または `Yu Gothic UI`（9pt〜10pt）で統一。1シート内でフォントの種類を混在させない。

### 6-2. 表示形式（Number Formats）
- **§6.3 金額数値**: `#,##0`（整数）または `#,##0.0`（小数点1桁）。マイナスは `(#,##0)` または `-#,##0`、ゼロは `-`（ハイフン）表示とする（会計スタイル: `_ ¥* #,##0_ ;_ ¥* -#,##0_ ;_ ¥* "-"_ ;_ @_ `）。
- **§6.4 パーセンテージ**: `0.0%`（必ず小数点1桁を明記）。`2%` ではなく `2.0%`。
- **§6.5 倍率（Multiple）**: `0.0x`（例: `7.5x`）。
- **§6.6 単位の明記**: 各シートのヘッダー部（B1またはC1付近）に、「（単位：百万円）」または「(JPY mn)」を必ず明記する。

## 7. 絶対禁止事項（Strictly Forbidden Practices）

以下の項目は、モデルの可読性・保守性・監査性を著しく損なうため、いかなる場合も**絶対禁止**とする：

1. **行・列の「非表示（Hide）」**:
   - 不要な行や中間計算を非表示（幅0・高さ0）にして隠すことは厳禁。折りたたむ場合は必ず**「グループ化（Data > Group）」**を使用する。
2. **数式内定数の埋め込み（Hardcoding inside formula）**:
   - `=C15*1.08`、`=D20*0.35` 等。定数は必ず前提セルとして独立させる。
3. **未検証のバランスシート放置**:
   - バランスシートの差額がゼロでない状態でモデルを提出・納品することは許されない。
4. **シートごとの時間軸不一致**:
   - あるシートではD列が2023年なのに、別のシートではC列が2023年になっているような列のズレ。
5. **外部リンクの切断・放置（Ref Errors）**:
   - `#REF!`, `#VALUE!`, `#DIV/0!`, `#N/A` などのExcelエラーを1箇所でも残したままにすること。
6. **ブラックボックス化**:
   - 1つのセルに100文字を超えるような長大な数式を組み、計算根拠を追跡不能にすること。

## 本規約の準拠チェック

モデル作成後は、必ず以下のコマンドを実行して機械的整合性を検証すること：
```bash
python3 scripts/check_model.py <作成したExcelファイルパス>
```
**判定が FAIL 0（Warningは理由を確認）となるまで、モデルを納品・共有してはならない。**
